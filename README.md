# KOSMIC

## Who this is for

- **Wet-lab scientists who don't run scRNA-seq pipelines themselves** — you have a gene, pathway, or programme you care about, and you want to know whether it's reproducibly changed in a specific cell type across the studies that have already been published, without writing scanpy code or stitching together your own analysis scripts.
- **scRNA-seq researchers who want to do cross-study meta-analysis properly** — single-dataset workflows are well-served by scanpy and Seurat, but combining results across studies is a different problem (methods disagree, gene universes don't align, "reproducible" is a contested word), and KOSMIC packages a defensible consensus framework (effect-size + rank + p-value pooling, plus orthogonal validation against proteomics and GWAS) so the gene list you publish holds up.

KOSMIC is **K**irk's **O**pen-source **S**ingle-cell **M**eta-analysis **I**ntegration and **C**onsensus Software — a desktop application for hypothesis-driven mining of public single-cell RNA-seq data. You can use it to download datasets from databases like the Gene Expression Omnibus (GEO), explore them, and ask questions about whether a gene, pathway, or programme is *reproducibly* changed in a cell type of interest — across the heart, brain, lung, liver, kidney, gut, or any other tissue with public scRNA-seq coverage.

## Why KOSMIC exists

Public single-cell repositories (e.g. GEO, ArrayExpress, the Broad Single Cell Portal) now hold thousands of datasets spanning every major organ system and most common diseases — cardiomyocytes, smooth muscle, and endothelial cells in heart failure; neurons, microglia, and vascular cells in Alzheimer's; alveolar epithelium, fibroblasts, and macrophages in IPF; and many more examples. For most cell-type-and-condition questions a researcher might ask, the data already exists, generated by single-cell sequencing studies across the world and deposited for the larger scientific community to benefit. The bottleneck is no longer generating new data; it's exploiting the data that is already public.

What's missing is a way to use this data the way biologists want to use data: to test specific hypotheses. The standard scRNA-seq workflow is exploratory by default — load, cluster, run differential expression, see what comes out — and existing single-dataset tooling (scanpy, Seurat, and their ecosystems) is well suited to that. But asking whether a *specific* gene, pathway, or programme is reproducibly changed in a *specific* cell type across multiple studies is a different question, and the methodology for it is still nascent. Recent work has begun to build the foundations: SumRank (Nakatsuka et al., *Nature Communications* 2025) introduced a rank-based reproducibility approach for case-control scRNA-seq meta-analysis; scMetaIntegrator (Vallania et al., bioRxiv 2025) extended the MetaIntegrator effect-size framework to paired single-cell designs; and Cao et al. (*Nature Communications* 2023) benchmarked weighted Fisher, fixed-effects, and random-effects p-value combination across batch-correction pipelines. Individual studies have also applied ad hoc meta-analysis to specific biological questions, such as Sun et al.'s analysis of tertiary lymphoid organ formation in vascular disease (*ATVB* 2023). But there is no integrated workflow that takes a researcher from a hypothesis to a tested answer — running the upstream per-dataset pipeline, the cross-study meta-analysis, and the validation against orthogonal data in one place — and no tool designed around hypothesis-driven analysis as the primary use case rather than as an afterthought to discovery.

KOSMIC packages this analysis category into a single graphical application. The per-dataset pipeline (QC → clustering → annotation → pseudobulk DE) and the cross-study meta-analysis run end-to-end, from raw counts to publication-ready figures, without leaving the application or writing analysis code.

KOSMIC is built around hypothesis-driven analysis as the primary use case. **Hypothesis mode** scores specific pathways or programmes in each study, meta-analyses the pathway-level signal across studies to test whether the programme as a whole is reproducibly changed, then drills down to the genes within it driving the signal. This is the workflow that lets researchers ask the questions they actually have — *is OXPHOS dysregulated in dopaminergic neurons in Parkinson's? Is complement signalling reproducibly altered in microglia in Alzheimer's?* — and get a tested answer rather than a gene list to interpret.

KOSMIC also provides the cross-study analogue of the standard exploratory workflow. **Discovery mode** runs unbiased gene-level meta-analysis across studies — what is consistently differentially expressed in this cell type, across these datasets — for cases where there isn't a specific hypothesis to test, or where the goal is to identify candidates for follow-up. Both modes share the same upstream per-dataset pipeline; they differ only in what gets meta-analysed across studies.

On top of the per-method results, KOSMIC produces a consensus gold-standard list of genes that are reproducibly differentially expressed across studies — the genes that survive every meta-analysis family (effect-size pooling, rank aggregation, p-value combination) *and* validate against orthogonal data (proteomics via Olink panels, GWAS via nearest-gene overlap). This is the high-confidence, conservative subset — the "most certainly different" genes you can put in a figure with a clear conscience. The argument for this consensus-plus-validation framework is the subject of a methods paper in preparation.

## Why pathway-level testing gains power

Hypothesis mode tests a curated gene set you've chosen *a priori*, which gives it a meaningful statistical advantage over genome-wide discovery: the multiple-testing burden is the size of your gene set, not 20,000 genes. Modest, consistent shifts across many genes in a coherent biological programme are exactly the kind of effect that real pathways produce, and exactly the kind of effect that genome-wide testing struggles to detect — they fail individually but accumulate as a pathway-level signal. A pathway score that survives meta-analysis across studies is a robust result even when no single gene in it would clear genome-wide significance on its own. Discovery mode and hypothesis mode are complementary; the gain comes from being able to ask a focused question when you have one.

## What KOSMIC answers

All KOSMIC analyses share the same shape: pick a cell type, compare two conditions (disease vs control, treated vs untreated, lesion vs margin — any case-vs-control design) within that cell type in each study, then combine the per-study results across studies. Within that shape, three flavours of question:

- *"Is APOE downregulated in microglia in Alzheimer's across studies?"* — single gene
- *"What genes are consistently changed in cardiomyocytes between failing and non-failing hearts across studies?"* — unbiased gene-level
- *"Is mitochondrial oxidative phosphorylation reliably dysregulated in dopaminergic neurons in Parkinson's, and which genes within it drive the signal?"* — pathway, then genes

The single-gene question can be answered from the discovery table, but if the gene belongs to a pathway you care about, going through the pathway route is more powerful. The pathway question is what hypothesis mode is built for.

## How a real study looks

A typical KOSMIC study answers a question like *"Is the disease-vs-control signature reproducible across K heart-failure datasets?"* The flow is:

1. **Per dataset (repeat for each study).** In the **scRNA** workspace: load → harmonise gene names → inspect → QC → cluster + annotate → subset to the cell type of interest. Then switch to the **DE** workspace (the dataset is pushed forward automatically) and run pseudobulk differential expression. KOSMIC writes the DE results into the dataset's `results/de_analysis/statistics/` folder.

2. **Across datasets.** In the **Meta** workspace, point KOSMIC at the parent folder containing all your datasets. It auto-scans for DE results, lets you pick a meta-analysis mode (hypothesis / discovery / comparison), and runs the analysis. Outputs land in `meta_analysis/` alongside your datasets.

State is preserved per-workspace, so hopping between workspaces never wipes what you were doing. Data flows downstream — scRNA → DE → Meta — so you can step back to scRNA at any time without losing your meta-analysis state.

## Workspaces

### scRNA Analysis

Seven sequential steps. Each unlocks once the previous one is complete:

| Step | What it does |
|---|---|
| **Load Data** | Imports H5AD, 10x H5, MEX, CSV, TSV, or Seurat RDS. GEO accession download supported. |
| **Gene Names** | Harmonises gene symbols against HGNC. |
| **Inspect** | Review metadata; map sample / condition / role columns. |
| **QC** | Doublet detection, optional ambient RNA correction, MT% / min cells / min genes filtering, normalisation. |
| **Cluster** | PCA, optional batch correction, Leiden, UMAP/t-SNE, cell-type annotation against bundled marker databases or CellTypist. |
| **Subset** | Filter to a cell type of interest. |
| **Figures** | Export publication figures (PNG + PDF, 300 DPI). |

### DE Analysis

Pseudobulk differential expression (DESeq2 by default; Welch CPM and Welch Raw also available). Two modes, picked on the *Choose Analysis* page:

- **Scoring mode** — *"I have a hypothesis; score these pathways."* Gene Set → Pathway DE → Figures. Bundled gene sets cover metabolic, GPCR, ion-channel, and other curated collections; you can also load your own.
- **Discovery mode** — *"What's differentially expressed, full-genome?"* Gene DE → Enrichment → Figures.

Both modes write results into the same `results/de_analysis/statistics/` folder so the Meta workspace can find them later.

### Meta-Analysis

Random-effects meta-analysis across DE results from multiple studies, with consensus across complementary methods (effect-size, rank-based, and p-value approaches — six methods in total). Reproducibility metrics, leave-one-out validation, and orthogonal validation overlays against proteomics (Olink CVD III, Olink Explore 3072) and GWAS (nearest-gene overlap with stratified enrichment).

Three modes, picked on the *Choose Mode* page:

- **Hypothesis mode** — *"I want to test these pathways across studies."* Pathway Explorer → Pathway MA → Consensus MA.
- **Discovery mode** — *"What's consistently DE across studies?"* Consensus MA only.
- **Comparison mode** — *"Which MA method should I use? Show me the trade-offs."* Individual Methods → Consensus Evaluation.

The result tabs visible after running consensus depend on the mode you chose: hypothesis mode focuses on pathway tabs, while discovery mode exposes the full set including Venn, enrichment, validation, and cross-dataset reproducibility.

### Figure Export

Compose publication-ready figures from analysed datasets — volcano plots, gene heatmaps, dotplots, forest plots, and multi-dataset heatmap+forest figures.

## Methods

KOSMIC's per-dataset and cross-study choices reflect specific positions on how scRNA-seq differential expression should be done. Each is supported by recent benchmarking work.

**Pseudobulk per sample.** Within each study, KOSMIC aggregates counts to one value per sample per cell type and runs DE on those pseudobulk values with PyDESeq2 (a Python implementation of DESeq2). This treats the biological sample, not the individual cell, as the unit of replication — the position established by [Squair et al. (*Nat Commun* 2021)](https://www.nature.com/articles/s41467-021-25960-2), who showed that single-cell DE methods that treat each cell as an independent replicate (Wilcoxon, MAST, edgeR-on-cells) inflate the effective sample size and produce large numbers of false positives. Welch CPM and Welch Raw are also available as alternative DE backends (switchable in *View → Settings*).

**Per-dataset clustering and annotation; DE on uncorrected counts with dataset as covariate.** Each dataset is clustered and annotated independently in the scRNA workspace — KOSMIC does not currently perform joint integration across datasets for annotation (planned for a future release). At the meta-analysis stage, DE is performed on the original uncorrected counts with `~ dataset + condition`, treating dataset as a covariate. This avoids batch-effect correction (BEC) on the expression matrix entirely, in line with the finding of [Nguyen et al. (*Nat Commun* 2023)](https://www.nature.com/articles/s41467-023-37126-3) that BEC methods which return corrected expression matrices (ComBat, MNN, scGen, Scanorama, ZINB-WaVE, etc.) distort log fold changes when DE is run on the corrected output, and that covariate modelling on uncorrected counts performs better. Nguyen's tests were on within-study batches rather than across published studies, but their direction of evidence — covariate modelling wins more clearly as batch effects grow larger — favours this choice in the cross-study regime KOSMIC operates in.

**Random-effects meta-analysis across studies.** Effect-size pooling uses DerSimonian-Laird ([DerSimonian & Laird, *Control Clin Trials* 1986](https://doi.org/10.1016/0197-2456(86)90046-2)) and REML, with Hartung-Knapp correction ([IntHout et al., *BMC Med Res Methodol* 2014](https://bmcmedresmethodol.biomedcentral.com/articles/10.1186/1471-2288-14-25)) applied where appropriate. Random-effects rather than fixed-effects is the appropriate choice across independent published studies, where between-study heterogeneity (τ²) from differing protocols, platforms, dissociation methods, and patient cohorts is structurally large — exactly the regime random-effects models are designed for. KOSMIC also implements rank-based aggregation (SumRank, gwOP) and p-value combination (Fisher, Stouffer), with consensus across all three method families. The methodological argument for consensus across complementary families, with orthogonal validation against proteomics (Olink) and GWAS, is the subject of a methods paper in preparation.

**Pathway-level testing.** Pathway scoring uses CAMERA-style competitive testing with variance-inflation correction. GO term enrichment uses the topGO-style elim algorithm via goatools.

## Folder layout

KOSMIC distinguishes two kinds of folder. Setting the wrong kind in the wrong workspace is the most common source of confusion:

- An **Analysis Folder** holds one dataset and everything derived from it. Set in scRNA (auto-pushed into DE).
- A **Project Folder** is the parent containing many Analysis Folders. Set in Meta.

Mental model: the Analysis Folder is a *document*; the Project Folder is a *portfolio*.

```
project_folder/                       ← Meta workspace setting
├── GSE12345/                           ← Analysis Folder (scRNA + DE setting)
│   ├── GSE12345.h5ad
│   ├── analysis_settings.json
│   └── results/
│       └── de_analysis/
│           ├── statistics/
│           │   ├── GSE12345_DE_deseq2.csv
│           │   ├── GSE12345_DE_welch_cpm.csv
│           │   └── GSE12345_DE_welch_raw.csv
│           └── figures/
├── GSE67890/                           ← second dataset
│   └── results/de_analysis/statistics/GSE67890_DE_*.csv
└── meta_analysis/                      ← written by Meta workspace
    └── consensus_results_*.csv
```

## Common gotchas

- **Re-run DE? Click Rescan in Meta.** If you re-run DE on a dataset after Meta is already loaded, Meta keeps its previously-scanned dataset list until you click *Rescan* (or re-set the project folder).
- **Open Folder behaves differently per workspace.** scRNA and DE expect an *analysis* folder (one dataset). Meta expects a *project* folder (the parent of many). Picking a single-dataset folder while Meta is active will report "no DE results found".
- **Three levels of navigation in Meta.** Activity rail → workflow step → result tab inside a step. Easy to lose track of which result tab you're on after running consensus.

## Installation

### System requirements

Windows, macOS, and Linux. KOSMIC is a desktop GUI and requires a graphical session — it does not run on headless servers without virtual display setup. 8 GB RAM minimum, 16-32 GB recommended for larger datasets. Heavily tested on Windows 11, moderately on Ubuntu 24.04, untested on macOS — please open an issue if you hit problems on macOS.

### Before you start

You need two things installed. Both are free and take a couple of minutes.

**Python 3.11 or newer.** Check what you have by opening a terminal
(Windows: press the Windows key, type `cmd`, Enter; macOS: Terminal;
Linux: your usual shell) and running:

```sh
python --version
```

If that says 3.11 or higher, you're set. If it says an older version,
or "not recognized" / "not found", install it from
[python.org/downloads](https://www.python.org/downloads/).

> **On Windows, tick "Add python.exe to PATH"** on the first screen of
> the installer. It is unticked by default, and leaving it unticked is
> the single most common reason the next step says `python` is not
> recognised. If you already installed without it, re-run the installer,
> choose *Modify*, and tick it there.

On macOS, the system `python3` is often too old; the python.org
installer is the reliable option. On Linux, `python3.11` from your
package manager is fine (`sudo apt install python3.11 python3.11-venv`
on Ubuntu/Debian).

**Git**, to download the code. From [git-scm.com](https://git-scm.com/downloads);
the defaults in the installer are fine. If you'd rather not, GitHub's
*Code → Download ZIP* button works too — unzip it and skip the
`git clone` line below.

**R, only if you will import Seurat `.rds` files.** KOSMIC converts
them by running R as a separate process, so R has to be installed on
the machine along with the **Seurat** and **Matrix** packages
(**SeuratDisk** is used if present). Get R from
[cran.r-project.org](https://cran.r-project.org/), then in R:

```r
install.packages(c("Seurat", "Matrix"))
```

KOSMIC finds R automatically -- on `PATH`, or under
`C:\Program Files\R` on Windows (newest version wins). This is
independent of how Python is installed. If you only ever load `.h5ad`,
`.h5`, `.mtx` or 10x folders, you do not need R.

### Install

Open a terminal in the folder where you want KOSMIC to live, then:

```sh
git clone <REPO_URL>
cd kosmic
python -m venv .venv
```

Then activate the environment. This is the one step that differs by
operating system, and you repeat it **every time you open a new
terminal** to use KOSMIC:

```sh
.venv\Scripts\activate          # Windows (cmd or PowerShell)
source .venv/bin/activate       # macOS / Linux
```

Your prompt should now start with `(.venv)`. Finally:

```sh
pip install -e ".[dev]"
python main.py
```

The install takes about five minutes and downloads roughly a gigabyte
(the scientific Python stack). No compiler is needed on any platform.

> If PowerShell refuses to run the activate script ("running scripts is
> disabled on this system"), run
> `Set-ExecutionPolicy -Scope CurrentUser RemoteSigned` once, answer Y,
> and try again. This is Windows' default policy, not a KOSMIC problem.

**Already a conda user?** Skip the venv lines: `conda create -n kosmic
python=3.11`, `conda activate kosmic`, then the same `pip install -e
".[dev]"`. Everything comes from PyPI either way.

### Optional features

```sh
pip install -e ".[all]"        # everything below
pip install -e ".[annotate]"   # CellTypist ML cell-type annotation
pip install -e ".[rds]"        # R RDS file reading
pip install -e ".[tsne]"       # openTSNE backend
pip install -e ".[monitor]"    # status-bar CPU/RAM monitor
```

Quote the extras — `zsh` treats bare brackets as a glob and will fail.

Two optional features depend on packages that are **not on PyPI**, so
they are not part of `[all]` and have to be installed separately:

- **SoupX** ambient-RNA estimation (the Decontaminate step also works
  without it, using a manually set contamination fraction)
- **DecontX** decontamination

Both are imported only when you use them, and the app tells you what is
missing rather than failing at startup.

KOSMIC is built on scanpy, anndata, PyDESeq2, PyQt6, and the standard scientific Python stack. Full pinned dependency list in [`pyproject.toml`](pyproject.toml).

## Bundled reference data

KOSMIC ships with curated reference data so most features work offline: pathway gene sets (Reactome, KEGG, HGNC), cell-type markers (PanglaoDB, CellMarker 2.0), GO ontology and human gene-to-GO (NCBI, GO Consortium), HGNC approved symbols, GWAS gene-position table (GRCh37, UCSC RefFlat), proteomics panels (Olink CVD III, Olink Explore 3072), and the Human Heart Cell Atlas as a cell-type annotation reference. KOSMIC also bundles endothelial cell subsets from four published cardiac heart-failure scRNA-seq studies (see *Try it in five minutes* above) for the tutorial walkthrough. All bundled data lives under `kosmic/reference/` and ships via `importlib.resources`.
